# Lattice operations

This directory contains the source-checkout deployment boundary for Lattice. [`install.py`](install.py) requires clean tracked and non-ignored untracked release inputs (runtime code, workflow packs, web source, installer, tests, locks, and ignore policy) at one unchanged Git revision through verification and publication; unrelated documentation, assurance journals, and Surface history do not block installation. It runs the synthetic assurance suites, copies legacy AXISVI runtime state through a verified snapshot when necessary, installs a non-editable versioned Python environment, atomically switches the active runtime while retaining the prior one, and installs the user launchd service and daily backup jobs. The request-serving daemon uses launchd's `Interactive` process class because cockpit responsiveness depends on it; the scheduled snapshot remains `Background` work.

Store initialization and server startup wait on the existing journal lock before issuing database writes. A backup in progress produces a visible wait message every thirty seconds instead of a SQLite timeout and crash loop. Pre-migration snapshots run before that shared hold; the hold ends before normal request serving, so later backup and rebuild operations remain available. The asynchronous startup wait is cancellable without leaving a background lock acquisition.

One installer or recovery process owns `maintenance.lock` for the whole operation. The lock is kernel-backed and is never unlinked; a stale PID does not block recovery, and a second installer refuses before changing service state. Both the general installer and the exact readiness-upgrade entrypoint use this boundary.

The installer builds the candidate, captures and verifies its rollback snapshot, and rehearses migration while the prior service remains available. Snapshot capture still reserves live writers; its integrity scans and migration rehearsal operate on independent captured state. The full logical equality comparison also finishes online. A process-local cutover identity brackets candidate verification and that comparison with one retained read-only SQLite connection, without holding a long read transaction. Its same-connection `data_version` detects committed writes, including replay connections that suppress tracking; connection loss or database file replacement invalidates qualification. Indexed event/change/integrity-chain tails, all migration-history rows, actual schema definitions and complete table/trigger coverage bind the verified baseline. Unknown tables, missing or altered triggers refuse qualification. The source schema cookie is bound to the live file; copied snapshot cookies and harmless physical layout differences are not treated as source identity.

Immediately before shutdown, the installer holds the existing database/journal admission locks, refuses active work, and rechecks this bounded database identity, snapshot-manifest mutation detector, runtime manifest hashes and exact prior publication controls (selector targets, shim/plist bytes and modes, and loaded jobs). Drift refuses with the service still running. The identity is a change detector, never fresh integrity proof: semantic integrity, required blob bytes and migration compatibility must already have been independently verified. Legacy and compressed snapshots bind through the online logical comparison and materialized snapshot schema/heads; no snapshot-format or application-schema migration is required. Only canonical migration and publication require the old service stopped; the five-minute HTTP readiness deadline starts after migration.

On macOS, a retained `kqueue` vnode watch is registered on the snapshot manifest and its containing directory before the full content hash and independent online verification. Final exclusion checks pending manifest write/attribute/rename/replacement events and pathname identity without rereading inventory bytes, including Backup/1–3 manifests with embedded inventory. The directory watch detects changes to the directory itself (attributes, rename, removal or revocation); unrelated sibling creation, writes and renames, including SQLite sidecars, leave the manifest qualified. The manifest's own watch and pathname identity detect its replacement. Manifest events remain invalidating even when bytes and timestamps are restored. Lost watches refuse qualification. Device/inode checks detect replacement; they never stand in for the online content hash. The watch covers ordinary local filesystem syscalls through this boundary; raw-device corruption, writable memory mappings and transient replacement of higher path ancestors remain outside its proof. Platforms without `kqueue` retain exact manifest hashing and compatibility, with a history-sized final filesystem cost rather than the macOS byte bound. The database sentinel has the same process-local lifecycle; neither detector substitutes for recovery evidence.

Trigger comparison accepts the shipped lexical templates with punctuation whitespace and the three registered historical `loom_*` function aliases. Quoted strings and identifiers remain exact, including internal whitespace; no-op bodies, altered hash arguments, unknown grammar and different trigger coverage refuse qualification. Historical database evidence is never rewritten to normalize spelling.

This boundary does not provide an admission drain or convergence under continuing writes: any commit during qualification invalidates the attempt, and active work still refuses maintenance. It does not detect arbitrary filesystem corruption without reading the affected bytes or fence noncooperating filesystem writers. Candidate startup intentionally changes schema cookies, so cutover identity ends before migration. Candidate-admission count checks and historical maintenance-record interpretation remain unchanged; a process-local sentinel cannot be reconstructed by a new recovery operator. Their growing-table costs, canonical migration snapshots and startup validation remain separate work.

Candidate validation checks shipped workflow definitions before shutdown. Publication and rollback use core conversation and durable-run readiness, exact runtime identity and startup recovery results. A failed external workflow remains visible in overall health and refuses its own routes; it does not make a working service fail restoration. This boundary also accepts older health payloads that report core readiness without attributing workflow failures to roots. Maintenance waits up to sixty seconds for transient startup-lock contention, while actual active work still refuses maintenance. Startup backfills append ledger changes only when a value resolves, so an ordinary restart does not masquerade as newly admitted work.

Before stopping writers, the installer saves the exact prior selectors, plist/shim bytes, rollback snapshot and recovery phase in private `maintenance.json`. SIGTERM, SIGINT and SIGHUP enter protected restoration. A killed process leaves that record for `./.venv/bin/python ops/install.py --recover` or the next normal installer to consume before capturing a new baseline. Migration children inherit a writer lock before execution; recovery excludes them throughout database restoration. A healthy interrupted publication is retained. Otherwise recovery refuses active work or newly admitted candidate state before stopping or overwriting it. Database restoration is checkpointed before restarting prior jobs, so repeated recovery cannot erase work served after that restart.

Failed candidate databases and SQLite sidecars remain privately retained under `acceptance/failed-upgrades/`. A failed restoration leaves the recovery record and keeps the incompatible prior runtime stopped. Process death recovery requires the recovery command or a subsequent installer; this does not claim an independent watchdog. Installation checks do not establish every provider's availability or whole-release qualification.

Snapshots store the consistent SQLite image as a bounded gzip payload and use copy-on-write clones for immutable content when the host filesystem supports them; restore materializes ordinary independent files, and legacy v1/v2 snapshots remain readable. The capture lock protects the database and file copy; integrity validation and compression operate on the independent captured state after releasing live writers. This preserves exact inventories and off-path restores while allowing ordinary work during backup validation. Migration rehearsal uses a scoped temporary restore with the same byte, inventory, and database checks, but without per-file drive-cache flushes: the retained immutable snapshot remains the recovery authority. Ordinary restores still synchronize files and directories before publication. The installer emits flushed phase messages for rollback capture, restored-state checks, migration, and preservation checks, so a supervised run’s log identifies the active stage.

Copied-store migration preserves every existing source-schema row exactly. Startup may append immutable provider profiles only when every definition field matches the candidate runtime's state-free built-in catalog; this exception does not permit rewritten profiles, invented projects or other source-row additions. The migration receipt retains that exact catalog alongside the preserved original-row counts.

[`authenticated_acceptance.py`](authenticated_acceptance.py) authors the complete synthetic freestyle graph through the running service, optionally qualifies workspace and native provider sessions, induces a typed provider failure, restarts launchd, and writes a content-bound acceptance report under the canonical data root. It never imports a personal corpus or records provider response text in the report.

[`qualify_release.py`](qualify_release.py) runs the fixed source and consumer suites plus the complete authenticated provider-profile matrix. [`qualify_interruption.py`](qualify_interruption.py) proves an installed daemon can reconcile an active provider lease after a process crash. [`qualify_browser.py`](qualify_browser.py) drives the installed cockpit and reconstructs its freestyle journey from base ledger records. [`qualify_restore.py`](qualify_restore.py) restarts the launchd service, continues a dormant browser-qualified branch, snapshots it, restores it into a separate root, and continues again from restored ancestry.

[`build_execution_closure_bundle.py`](build_execution_closure_bundle.py) binds the exact generated-object evidence set into one canonical closure bundle. [`verify_execution_consolidation.py`](verify_execution_consolidation.py) is the independent closure boundary for Lattice 0.3 execution. It reads base SQLite tables, content-addressed blobs, raw runtime receipts, immutable provider profiles, installed package and binary attestations, consumer source trees, historical journal bytes, and exact credential canaries. It refuses `lattice_execution_ready` when the installed runtime manifest is absent or any execution evidence is unresolved.

[`qualify_context.py`](qualify_context.py) qualifies Claude's provider-facing context representation through the installed service. `prepare RUN_ROOT --fixture-dir DIAGNOSTIC_ROOT` freezes the retained packaging diagnostic's original synthetic eligibility prompt/schema, five cases, runner hashes, and installed runtime before any model call. `run RUN_ROOT --case CASE_ID` performs exactly one case in the declared order: `eligibility`, `parent_a`, `parent_b`, `edited_join`, `conflicting_references`. Run with the source environment's Python after a clean install. Every started case is reserved permanently; a failure, timeout, changed input, or missing earlier result stops admission. On interruption, inspect the case's sealed invocation and native journals rather than resubmitting. Requests have no tools or network authority; the 120-second bound cancels only that case. Exact answers, source quotations, and raw provider receipts—not a model's self-assessment—determine the result. Retain the run directory and native journals; no production queue is dispatched.

[`qualify_conversation_native.py`](qualify_conversation_native.py) qualifies the exact installed Fable 5.1 read-only route one round at a time. Run it with the current immutable runtime's Python and a private run directory. `prepare` freezes the runtime, executable, route, runner and unpredictable canaries; `run --step completed-first`, then `completed-continued`, proves ordinary native recall. `admit --boundary completed` publishes that independent capability before the interruption cases. `interrupted-first` cancels at exposed activity before terminal output, and `interrupted-continued` must recall the token without file retrieval or a new input channel before `admit --boundary interrupted`. Each started round is reserved permanently; provider failures stop advancement. `reconcile --step STEP` finishes a lost operator acknowledgement from its existing journal without dispatching again. A separately proven completed boundary remains usable if later qualification fails. Raw journals remain private, and immutable qualification receipts bind the actual installed package tree and executable.

The installed service never imports the development checkout. Runtime state, versioned environments, and backups live under `~/Library/Application Support/Lattice/`; logs live under `~/Library/Logs/Lattice/`. `~/.local/bin/lattice` is a stable executable shim that binds this personal deployment to AXISVI and follows the atomically selected runtime, so it works from any shell directory.
