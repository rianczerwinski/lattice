# Recoverable conversations

Execution home for the approved durable-conversation implementation. The governing plan is [the durable-work plan](../../DURABLE-WORK-AND-PRIMARY-UX-PLAN.md#recoverable-conversation-execution-slice); the live owner handoff specifies packets A–F and takes precedence over earlier outlines.

- `baseline.json` binds the source and observed execution environment before implementation.
- `status.md` records completed packets, evidence, blockers, and the next entry point.
- Permanent checks live in the normal test suite. Installed qualification receipts belong here only after actual qualification.
- `inspect_persistence.py DATA_ROOT CONVERSATION --expected EXPECTATIONS.json` independently reads base SQLite rows and content-addressed bytes. Its expectation file contains hand-authored `completed` ordinal/request/response hashes, with optional `completed_count`, `execution_count` (associations, not external dispatches), and `owning_task_ref`. It checks request identity, response/checkpoint linkage, checkpoint chains, project boundaries, accepted invocation state, artifact bytes, steering references and observation offsets. The generated inspection report is limited to persistence; authentication, native recall, browser behavior, external effects and overall closure require their own evidence. `test_inspect_persistence.py` includes an actual-store compatibility case and self-consistent corruption controls.
- `qualify_live_conversation.py` drives one installed public-API action per command, using the runtime's Python with `AXISVI_ROOT=/Users/rian/AXISVI`. `prepare PRIVATE_ROOT --project PROJECT --provider anthropic|openai` fixes the route and token. `run PRIVATE_ROOT --step create|first|second|pending|interrupt|continue|inspect` retains requests before dispatch, uses owning-task discovery, verifies earlier exact-token responses before advancement, and interrupts only after the selected pending round exposes work. Inspect and independently bind each completed boundary before the next action. Re-entry replays identical saved requests before reading a new preview; failures never launch replacement calls automatically. The controller records a journey, not a qualification verdict. Use the independent reader, raw execution manifests and provider journals to establish the result.

Raw provider transcripts and credentials remain in private Lattice runtime storage. No claim is closed by a successful uninterrupted call or by missing/skipped acceptance.
